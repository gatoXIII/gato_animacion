## CHANGE-001 — Aplicación de ADR-003 (lagunas math)

- **Motivo**: Cerrar lagunas L-MATH-01 a L-MATH-06 detectadas en Etapas 1–3.
- **Contrato anterior**:
  - `Matrix3x3.invert()` usaba umbral `1e-10` hardcodeado.
  - `Vector2.equalsApprox(other, epsilon = 1e-6)` tenía default.
  - `Matrix3x3.equalsApprox(other, epsilon = 1e-6)` tenía default.
  - `Transform.setPosition/setRotation/setScale` usaban `1e-6` local.
  - `Matrix3x3.constructor` no documentaba rechazo de typed arrays.
- **Contrato nuevo**:
  - `Matrix3x3.invert()` usa `EPSILON_MATH = 1e-9` (ADR-003-D1).
  - `Vector2.equalsApprox(other, epsilon)` exige epsilon explícito; lanza si falta.
  - `Matrix3x3.equalsApprox(other, epsilon)` exige epsilon explícito; lanza si falta.
  - `Transform.setPosition/setRotation/setScale` usan `EPSILON_MATH` (ADR-003-D4).
  - `Matrix3x3.constructor` rechaza typed arrays explícitamente (ADR-003-D5).
  - Nuevo módulo `math/Epsilon.js` con `EPSILON_MATH = 1e-9` (ADR-003-D1).
- **Módulos afectados**: `math/Vector2.js`, `math/Matrix3x3.js`, `math/Transform.js`, `math/Epsilon.js` (nuevo).
- **Funciones afectadas**: VEC-010, MAT-001, MAT-008, MAT-012, TRN-003, TRN-006, TRN-009, EPS-001 (nuevo).
- **Invariantes afectadas**: ninguna global; se refuerza consistencia numérica.
- **Tests afectados**: todos los que llamaban `equalsApprox` sin epsilon deben actualizarse; nuevos tests de ADR-003.
- **Compatibilidad**: BREAKING para callers de `equalsApprox` que omitían epsilon. Requiere pasar epsilon explícito.
- **Referencia**: `docs/decisions/ADR-003-lagunas-math.md`.
